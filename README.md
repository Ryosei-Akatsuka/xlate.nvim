# trans-nvim

Neovim 上でコードや Markdown の文章を翻訳し、**元のバッファを変更せず表示だけ追加**する翻訳プラグイン。

翻訳バックエンドには [translate-shell](https://github.com/soimort/translate-shell) の `trans` CLI を使用します。

```cpp
// hello
// i am god
```

`:Trans` を実行すると、バッファはそのままでこう表示されます（`virt_lines` による仮想行）。

```cpp
// hello
// i am god
// こんにちは
// 私は神です
```

## 特徴

- **元のバッファは一切変更しない** — 翻訳結果は `extmark` の `virt_lines` だけに描画される
  - 保存しても翻訳結果は書き込まれない
  - ヤンク・編集の対象にならない
  - 元ファイルを汚染しない
- **Tree-sitter による翻訳対象の検出** — 解析（検出）・翻訳・表示をそれぞれ分離
- **非同期・逐次表示** — 翻訳中もエディタはロックされず、訳文ができ上がった順に1行ずつ表示される
  - 各行は `trans` プロセス（最大 `max_concurrency` 並列）に委譲され、結果が届くたびにその場で描画される
  - キャッシュヒット分は即座に表示される
  - 実行中に `:TransClear` でいつでも中断できる
- **編集時の自動更新** — 表示中のバッファは編集後に自動で再翻訳（デバウンス付き・オプトイン、`:TransClear` で停止）
- **ファイル形式ごとに翻訳単位を最適化**
  - コード: コメントブロック単位（連続した `//` は 1 ブロック、`/* ... */` はブロック全体）
  - Markdown: 見出し・段落・リスト・引用など**意味のある文章単位**（行単位では分割しない）
  - コードブロックなどの翻訳不要な部分は対象外
- **SHA-256 ベースの翻訳キャッシュ** — 同じ文章は 2 度と `trans` を実行しない（セッションを跨いで永続化）
- **バックエンド分離** — `trans` との通信は `translator.lua` の中だけ。差し替え可能

## 必要条件

- Neovim 0.10 以上
- [translate-shell](https://github.com/soimort/translate-shell)（`trans` コマンド）
  - `brew install translate-shell` など
- Tree-sitter パーサー（対象ファイル形式分）
  - コード: `c` / `cpp` など
  - Markdown: `markdown`

## インストール 

[lazy.nvim](https://github.com/folke/lazy.nvim) の場合:

```lua
{
  "ryosei/trans-nvim",
  config = function()
    require("trans").setup({
      target = "ja",
    })
  end,
}
```

`setup()` は省略可能です（省略時はデフォルト設定で動作します）。

## 使い方

| コマンド           | 動作                                       |
| ------------------ | ------------------------------------------ |
| `:Trans`           | バッファを翻訳して仮想行を表示             |
| `:TransClear`      | 仮想行を削除                               |
| `:TransToggle`     | 表示中なら削除、非表示なら翻訳             |

`auto.enabled = true` にしておくと、翻訳を表示中のバッファは**編集のたびに自動で再翻訳**されます（[設定](#設定) の「自動更新」を参照）。

## 設定

```lua
require("trans").setup({
  target = "ja",               -- trans の翻訳先 (":ja", "en:ja", "ja:en" なども可)
  cmd = "trans",               -- 翻訳コマンド
  extra_args = { "-b", "-no-ansi" },
  timeout = 10000,             -- 1 行あたりのタイムアウト (ms)
  max_concurrency = 2,         -- 同時に起動する trans プロセス数（デフォルト: 2）
  cache = {
    enabled = true,
    path = vim.fn.stdpath("cache") .. "/trans-nvim/cache.json",
  },
  highlight = "TransTranslated", -- 仮想行に使うハイライトグループ
  notify = true,                 -- 完了サマリを通知する
  auto = {                       -- 編集後の自動再翻訳（デフォルト: オフ）
    enabled = false,             -- 有効化すると :Trans 済みバッファを自動更新
    events = { "TextChanged", "TextChangedI", "InsertLeave" },
    debounce = 800,              -- 最終編集から待つ時間 (ms)
  },
})
```

仮想行の色はデフォルトで `Comment` にリンクされます。

```lua
vim.api.nvim_set_hl(0, "TransTranslated", { fg = "#7f849c" })
```

### 並列数の目安

`max_concurrency`（同時起動する `trans` プロセス数）は実測しています。16 行 × 各並列数 3 回（キャッシュ無効）:

| 並列数 | 平均所要時間 | スピードアップ | 初回表示遅延 |
| ---: | ---: | ---: | ---: |
| 1 | 12,213 ms | 1.00x | 793 ms |
| **2** | **3,791 ms** | **3.22x** | **292 ms** |
| 4 | 2,278 ms | 5.36x | 324 ms |
| 8 | 1,591 ms | 7.67x | 411 ms |
| 16 | 1,488 ms | 8.21x | 608 ms |

- **デフォルトは 2**。初回表示が最速（約300ms）で、総時間も約 3 倍に短縮できるため
- 最大スループットが要る場合は `max_concurrency = 8`（8 並列で 7.7x、16 並列は +7% しか伸びません）
- 逐次表示中は初回の1件が届いた時点から描画が始まるため、体感速度は「初回表示遅延」に現れます

### 自動更新

`auto.enabled = true` にすると、**翻訳を表示中のバッファ**は編集のたびに自動で再翻訳されます。

```text
:Trans で表示 → コメントを編集
      ↓ debounce (800ms) — 連続編集は 1 回に集約
silent な再翻訳（サマリ通知なし）
      ├─ キャッシュ済みの単位 → 即座に再描画
      └─ 変更・新規の単位のみ trans を実行 → 逐次表示
```

- **開始条件**: そのバッファで一度 `:Trans` を実行したこと
- **停止条件**: `:TransClear` / `:TransToggle`（オフ）— そのバッファの自動更新は停止
- **翻訳中に編集した場合**: 結果を破棄して警告する代わりに、完了後に自動で再翻訳（部分表示はその間保持される）
- **無変更はスキップ**: undo などで翻訳済みテキストに戻った場合は再実行しない
- `max_concurrency` とキャッシュがそのまま効くため、**未変更の単位にはバックエンドを呼びません**
- 自動更新の実行は完了サマリ通知を出しません（失敗時の警告は出ます）

## 仕組み

```text
コード / Markdown
      ↓
parser/        (Tree-sitter で翻訳対象を検出)
      ↓
翻訳単位 (unit)
      ↓
translator/    (trans CLI に非同期で委譲 / cache はここで参照)
      ↓  行ごとに完了するたびにコールバック
renderer/      (extmark + virt_lines をその場で更新 ← 逐次表示)
```

翻訳中もエディタはロックされません（`trans` はプロセスとして並列起動され、結果はイベントループ上で処理されます）。

### 翻訳単位

**コード** — コメントを Tree-sitter で検出し、単位を生成します。

| 入力                                | 単位                          |
| ----------------------------------- | ----------------------------- |
| `// hello`                          | 単一行コメント                |
| `// hello` / `// i am god`（連続）  | 1 つのコメントブロック        |
| `/* ... */`                         | ブロック全体（内部は行ごとに翻訳） |
| `int x; // trailing`                | 行に食い込むコメントは独立した単位 |

連続したコメントは 1 つのブロックとして扱い、翻訳は**元の改行単位ごと**に行って結果をまとめて表示します。

**Markdown** — 見出し・段落・リスト項目・引用を翻訳単位とします。空行や Markdown の構造を境界として使い、1 行単位では分割しません（折り返された段落は結合してから 1 回だけ翻訳します）。`fenced_code_block` などコードを含むブロックは翻訳対象外です。

### 表示

翻訳結果は `nvim_buf_set_extmark()` の `virt_lines` で描画されます。見えている翻訳行はバッファ上には存在しないため:

- ファイル保存時に翻訳結果は書き込まれない
- コピー・編集の対象にならない
- 元ファイルを汚染しない

#### 非同期・逐次表示

`trans` は非同期に起動され（最大 `max_concurrency` 並列）、`translate()` は即座に制御を返します。各行の結果が届き次第、そのユニットの仮想行を**その場で更新**するので、訳文はできたものから順に現れます。

```text
:Trans 実行（即座に制御を返す）
  ├─ 0.2s  // こんにちは                ← できた行から表示
  ├─ 0.4s  // こんにちは
  │         // 私は神です              ← あとから埋まる
  └─ 0.6s  全件完了 → サマリ通知
```

- 翻訳中もカーソル移動・スクロール・その他の操作は通常どおり可能
- キャッシュヒット分は開始と同時に表示される
- 翻訳中に**テキストが編集**された場合は行がずれるため、結果を破棄して警告します（自動更新が有効なバッファでは破棄の代わりに、完了後に自動で再翻訳します。また `changedtick` が上がっても内容が同じ場合は保持されるため、翻訳中の `:write` では結果は失われません）
- 翻訳中に `:TransClear` / `:TransToggle` を実行すると、バックエンドへの起動を止めてその場で中断します

### キャッシュ

```text
source text → SHA-256(lang + text) → cache → hit なら trans を呼ばない
```

キャッシュはメモリ上と `stdpath("cache")` 以下の JSON ファイルに保存され、Neovim 再起動後も有効です。

## 構成

Neovim のランタイム規約（`plugin/` は自動読み込み、モジュールは `lua/`）に合わせています。

```text
plugin/
└── trans.lua               # エントリポイント（コマンド登録・デフォルトハイライト）
lua/trans/
├── init.lua                # setup / translate / clear / toggle / is_translating
├── parser.lua              # 形式ごとに検出器を選択
├── parser/
│   ├── code.lua            # Tree-sitter によるコメント検出 (C/C++ ほか)
│   └── markdown.lua        # 意味のある文章ブロックの検出
├── translator.lua          # trans CLI との非同期通信（バックエンド分離）
├── renderer.lua            # virt_lines の逐次描画（begin / show）
├── auto.lua                # 編集後のデバウンス付き自動再翻訳
└── cache.lua               # 翻訳キャッシュ
tests/
└── run.lua                 # テストスイート
```

## テスト

```sh
nvim --headless -u NONE -c "luafile tests/run.lua" -c "qa!"
# 164 checks, 0 failures
```

キャッシュ・C/C++ コメント検出（単一行 / 連続 / ブロック / 行内）・描画・Markdown 検出・実バックエンドを使った E2E（バッファ非改変・保存されないこと・キャッシュヒット）に加え、以下も検証します。

- **非ブロック**: `translate()` が即座に復帰すること、翻訳中にイベントループが動き続けること
- **逐次表示**: 先に完成したブロックから表示され、完了前に部分的な状態が観察できること
- **中断**: 翻訳中に `:TransClear` した場合にマークが残らないこと
- **`:write` 耐性**: 翻訳中の単なる保存で結果が破棄されないこと
- **自動更新**: 編集でデバウンス後に再翻訳され、連続編集が1回に集約されること・`:TransClear` で停止すること・翻訳中の編集では破棄ではなく再スケジュールされること・自動実行は通知を出さないこと・翻訳済みテキストへの undo ではスキップすること・バッファ削除でタイマーが解放されること
